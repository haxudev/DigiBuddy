# Runtime adapter contract

The skill is runtime-neutral: it names capabilities, never a product. This
document is the contract, and `agent_maturity` implements it — so in most hosts
you bind nothing, you just call the tools.

Read this when wiring the pack into a host that has no adapter yet, or when a
host cannot do something the interview needs.

## The ask

Every question is an **`AskSpec`**, one object with three kinds:

| Kind | Input | Answer | Native control | Text-only fallback |
| --- | --- | --- | --- | --- |
| `single` | 2–5 mutually exclusive options | exactly one option id | selection card, radio, CLI select | lettered list; ask for one letter |
| `multi` | 2–8 independent options | zero or more option ids | multi-select, checkboxes | lettered list; ask for comma-separated letters |
| `text` | one focused prompt, options generated by the agent | one string | selection card plus a free-text slot | plain question; wait for the next turn |

Returned by `maturity_next_question` as:

```json
{
  "id": "A1.qa",
  "kind": "single",
  "header": "A1 Vision",
  "prompt": "Which of these best describes ...?",
  "facilitator_note": "Read the options as written ...",
  "options": [{ "id": "a", "label": "Nobody has said out loud ...", "description": "Whoever is curious ...", "group": "low" }],
  "groups": [{ "id": "high", "option_ids": ["d", "e"], "label": "None of these ..." }],
  "required": true,
  "allow_free_text": false,
  "option_source": "fixed",
  "text_fallback": "…the whole question as a lettered list…",
  "card": { "mode": "cards", "cards": [ … ], "text_fallback": "…" },
  "card_capped": { "mode": "cards", "cards": [ …band…, …refine… ] },
  "meta": { "pillar": "A", "dimension": "A1", "question_type": "...", "progress": {} }
}
```

Rules that are not negotiable:

- **Never present a `multi` as mutually exclusive**, and never present a
  `single` as a multi-select.
- **Send back option ids or labels.** A card tool answers with the display
  string, so both resolve; the tool also accepts a display letter or a 1-based
  index, so a chat fallback can pass through what the customer typed. Two
  options may never share a label, and `AskSpec` refuses to be built if they do.
- **`single` options carry no level numbers.** They are deliberately absent from
  the object, so they cannot leak into the room. Do not look them up and
  volunteer them.
- **`facilitator_note` and `meta.judge_rule` are for you, never for the
  customer.** A card has no facilitator-only region, so neither is ever rendered
  into one. They are deliberately absent from `text_fallback`, from every card,
  and from the MCP elicitation message.
- **`allow_free_text: false` means switch the host's own free-text entry off.**
  It is set on the anchored choice, whose five options are exhaustive and whose
  position is the score.
- **`option_source: "agent"` means you write the options.** `meta.option_rule`
  states the constraint, and `answer_source` on `maturity_record_answer` says
  which channel the answer came back through.

## Rendering: the card projection

`ask.render_plan(caps)` turns one `AskSpec` into the cards a host can actually
draw. `maturity_next_question` pre-computes two of them.

| Field | Meaning |
| --- | --- |
| `mode` | `cards`, or `plain-text` when the card cannot carry the question |
| `cards[].header` / `.question` / `.options[]` / `.select_many` | the five portable fields |
| `cards[].free_text` | the slot's prompt, or `null` meaning "switch free text off" |
| `cards[].follow_up_id` | on a band card, the option that opens the refine card |
| `warnings` | for example `header-shortened`, `group-collapsed` |

**Rendering never changes what gets recorded.** A five-option question drawn as
one card and the same question drawn as a band card plus a refine card resolve
to the same option id, and `answers.json` never learns which route was taken.
`render_plan` may reshape the cards; it may not reshape the answer.

Per-host bindings, limits and evidence grades live in `choice-cards.md`.

## How each host projects it

| Host | Projection | Where |
| --- | --- | --- |
| Agent runtime | its own selection card | `render_plan()`, `choice-cards.md` |
| MCP | `elicitation/create` `requestedSchema` | `mcp/elicit.py` |
| LangGraph | `interrupt(payload)` | `src/agent_maturity/adapters/langgraph.py` |
| Terminal | prompt + `input()` | `adapters/terminal.py` |
| Any SDK | `ask.to_json_schema()` | `askspec.py` |
| Chat only | `ask.to_text_prompt()` | `askspec.py` |

### MCP elicitation, exactly

`requestedSchema` is a flat object of primitives, so there is one
`elicitation/create` per question. The main answer is `answer`; a multi-select
that also permits typing carries a sibling `answer_text` string.

| Kind | `2025-11-25` | `2025-06-18` |
| --- | --- | --- |
| `text` | `{"type":"string"}` | same |
| `single` | `{"type":"string","oneOf":[{"const","title","description"}]}` | `{"type":"string","enum":[...],"enumNames":[...]}` |
| `single` + free text | `{"type":"string","examples":[...]}` — an enum would reject the customer's own words | same |
| `multi` | `{"type":"array","items":{"anyOf":[{"const","title","description"}]},"minItems","maxItems"}`; optional sibling `answer_text` | no array form exists — one `boolean` property per option plus optional `answer_text` |

`mode: "form"` is sent on `2025-11-25` and omitted on `2025-06-18`, where form
is the only mode. The response `action` is `accept`, `decline` or `cancel`;
only `accept` carries `content`. A decline or a cancel must leave a resumable
session, never a half-written answer.

## Persistence

| Operation | Contract |
| --- | --- |
| `read_json` | absolute path in, parsed object out |
| `write_json_atomic` | temporary sibling, `fsync`, then `os.replace` |
| `run_local` | executable plus arguments; exit code, stdout, stderr |

`session.write_json_atomic` implements this. A 30–60 question customer session
without durable state is **not supported**: if a host cannot persist atomically,
stop before the scored interview rather than risk losing an hour of the
customer's time.

## Roots

- **`<skill-root>`** is the directory containing `SKILL.md`. Resolve it from the
  runtime's loaded-skill metadata, never from the process working directory.
- **`<session-dir>`** is a customer-private directory holding `answers.json` and
  the generated artifacts. Never write real customer answers under `fixtures/`
  or inside the skill package.

The package finds its own reference data through `paths.py`, which checks
`AGENT_MATURITY_REFERENCES`, then the installed wheel's `agent_maturity/data/`,
then `<skill>/references/` for a vendored install, then the source checkout.
`AGENT_MATURITY_BANK` overrides the bank alone, which is how an industry variant
is loaded.

## State and resume

`maturity_start_session` creates `answers.json` before the first scored
question, and every `maturity_record_answer` persists **before** returning the
next question. Nothing else is needed for resume.

```json
{
  "schema": "agent-maturity-answers/2",
  "engagement": { "organization": "...", "tier": "standard", "language": "en" },
  "progress": { "status": "in_progress", "cursor": "A1.qa", "asked": ["framing.language"] },
  "answers": { "A1": { "anchor": 400, "evidence": "...", "quote": "...", "qc": "...", "qc_passed": false } }
}
```

**The cursor is advisory.** Position is derived from `answers` and `asked`, so a
lost, stale or hand-edited cursor cannot corrupt the interview. On resume, call
`maturity_session_status` and replay `resume_sentence` to the facilitator in one
sentence, then continue. Never re-ask a completed question unless the customer
revises the answer.

`progress.status` becomes `complete` only when all fifteen sub-dimensions have an
anchor and every tier-required follow-up is recorded.

## Failure behavior

| The host cannot… | Then |
| --- | --- |
| render a selection card | use `text_fallback`; the tool accepts ids, labels, letters and indices |
| fit five options on one card | use `card_capped`; the band card plus its refine card record the same answer as one card would |
| render a multi-select | `render_plan` returns `plain-text` rather than dropping to single-select, because a quiet downgrade discards choices the customer made and they never see it happen |
| offer a free-text slot | `render_plan` returns `plain-text`; a synthetic "type here" option cannot collect the text it promises |
| ask the user directly | do not call `maturity_run_interview` — it is not advertised to you anyway |
| persist JSON atomically | stop before the scored interview |
| execute locally | the interview can finish and hand over `answers.json`, but do not claim the assessment or report was produced |

## If you are not using the tools at all

The contract still holds; you are implementing it by hand. Read
`question-bank.json`, walk pillars A–E and their three sub-dimensions in order,
ask the anchored choice, then the evidence probe, then the disconfirming probe
only when the anchor was 400 or 500, and batch the evidence probe per pillar in
`pulse`. The tiers block in the bank declares all of this as data.

Two card-specific pieces are derived rather than stored, and
`src/agent_maturity/bank.py` is the reference implementation of both:

- an anchor's card **label** is its authored `short` for that language, or the
  first sentence of `text`, with the remainder becoming the description;
- a disconfirming probe's **`fail_exemplar`** is the authored override, or the
  quoted failing answer inside its own `pass_test`.

Then write the answers file above and run `agent-maturity score`.
