# Profile: 社交获客与线索质量

- **Profile id:** social-customer-acquisition
- **Base profile:** none

## Dimensions to clarify

| Dimension | Deferrable | Why it decides the shape of the work |
| --- | --- | --- |
| **[decision-cycle] 品类决策周期** | no | 高客单长决策（沙发：2 周至 3 个月）与冲动消费的打法完全不同。前者「一次评论就成交」不存在，指标必须是中间态（预约、到店、索取资料）；后者才谈得上转化率。搞错这一条，整个漏斗的分段和目标值都是错的。 |
| **[geo-serviceability] 地域可服务性** | no | 重物流品类里地域是硬约束而不是加分项：不在覆盖城市的人，需求再强也难以服务。门店与经销商清单必须在评分之前拿到，拿错清单会系统性误判整个地区的线索价值，而这在漏斗数字上看不出来。 |
| **[intent-evidence-standard] 意向证据标准** | no | 「什么算一条合格线索」必须在采集之前定死，而且要定成可核对的证据而不是形容词。「需求明确」不是标准，「原文里出现尺寸、预算或面料之一的具体约束」才是。定不下来，评分就退化成打分者的心情，第二轮也没法和第一轮比。 |
| **[outreach-execution-mode] 建联执行模式** | no | 只产出草稿由人执行，还是自动发送？这决定安全边界放在哪里。稳妥做法是让发送类能力压根不存在，安全性由「能力没有」保证，而不是靠提示词请求别发。上线后再改这一条等于改架构。 |
| **[quota-and-budget] 额度与预算** | no | 采集是计费的，建联额度是有限的。任务级与日级采集预算必须由真正发起付费调用的那一侧用可信账本执行；本地自报数值不是闸门，只能做批次提示。超限时还要给出替代方案，否则只会无脑重试。 |
| **[data-retention-boundary] 数据留存边界** | no | 存什么、存多久、给谁看。消费者原文、账号 ID、地域推断都是个人信息。哪些进交付物、哪些只留在内部、哪些根本不该落库，要在采集之前定，不是在交付前删。 |
| **[success-definition] 成功的定义** | no | 「获客」可以指曝光、线索数、合格线索数或到店数。这四个的最优打法互相冲突：追曝光会去跟审美类热点，追合格线索就必须砍掉它们。不先定死，复盘时每个人都能证明自己成功了。 |

## Step skeleton

1. **[step-define-success] 定死成功的定义与合格线索的证据标准。** 在任何采集之前完成，标准要写成可核对的形式而不是形容词。
2. **[step-geo-and-price] 拿到地域覆盖清单与价格带。** 这是客户事实而不是可推断的东西；拿不到就明确标注「用了默认值」，并让这个标注出现在交付物里。
3. **[step-two-gates] 设两道闸门。** 采集预算由真正发起付费调用的一侧按任务级与日级执行，建联额度由发送系统执行；本地检查只做离线提示，超限时给出替代策略。
4. **[step-platform-first] 先问平台再想关键词。** 搜索联想词与热榜是低成本调用，用它们拿到真实长尾表达，再组合关键词矩阵。
5. **[step-two-hop-collect] 两跳采集。** 搜到矿脉帖，再挖它的评论区；只搜笔记不挖评论是这个领域最常见的浪费。
6. **[step-normalise-first] 归一化之后再进上下文。** 原始响应先归档再归一化，避免把结构变更当成内容变化读。
7. **[step-timeline-before-score] 评分之前先补时间线。** 对打算给高分的人先看历史发帖，一次调用就能把时间窗判断从「猜」变成「看」。
8. **[step-judge-then-derive] 先判断、再校验和派生。** 逐人按 rubric 给出判断分与证据，再由确定性计算得出地域匹配、预算匹配、总分与等级；不要让判断环节直接填写派生结果。
9. **[step-draft-then-review] 草稿先过硬规则再进审批。** 使用真实线索 ID 与可寻址原文，检查归属、违禁词、引用真实性与模板化程度。
10. **[step-segment-efficiency] 逐段算效率，只认最低的那一段。** 瓶颈在哪就打哪，不要「为了完整性」每轮从头跑一遍。

## Acceptance criteria

- **[criterion-evidence-quote]** 每条线索的意向判断都能定位回该作者本人的原文，逐字可核对。
- **[criterion-unknown-over-guess]** 证据不足时标注为未知或给低分，而不是用高置信度补齐。
- **[criterion-geo-from-source]** 地域可服务性来自客户提供的覆盖清单，不是从文本推断出来的。
- **[criterion-stable-ids]** 信号、作者、线索、互动、转化各级都保留真实且唯一的 ID 与逐级关系，重复或断链视为失败而不是静默去重。
- **[criterion-derived-deterministic]** 总分、等级与各类匹配度由确定性计算得出，可复算复现。
- **[criterion-failure-not-empty]** 接口报错、超时与解析失败被记为失败，绝不记成「这个关键词没有人」。
- **[criterion-outreach-addressable]** 每份建联草稿都绑定真实线索 ID 与可寻址原文，且不能原样发给第二个人。
- **[criterion-pii-boundary]** 交付物中的个人信息范围与留存期限，符合采集前约定的边界。
- **[criterion-funnel-segmented]** 复盘按漏斗分段给出各段效率，并指明最低的那一段。

## Known pitfalls

**[pitfall-inflated-confidence] 虚高的置信度。** 证据不足时给了高分或高置信度，会污染整个漏斗，最终产出一份看起来饱满、实际无法执行的线索清单。宁可标未知，宁可给低分。

**[pitfall-fabricated-quote] 模板化的「个性化」与编造的引用。** 一条能原样发给两个人的评论不是建联；更危险的是编造的引用，它骗得过审批人，骗不过对方本人。引用必须逐字可核对。

**[pitfall-failure-as-empty] 把「采集失败」读成「结果为空」。** 接口报错或上游结构变更导致解析不出记录，如果被读成「这个关键词没有内容」，后面每一个结论都建立在空气上。解析不出来要报错，不要返回空数组。

**[pitfall-geo-inferred] 从文本推断地域。** 一句「北方冬天冷」不构成可服务性判断。地域是硬约束，推断出来的地域会系统性高估或低估整片区域的线索价值，而且在汇总数字上完全看不出来。

**[pitfall-vanity-metric] 追曝光当成追获客。** 审美类热点带来的互动量最高，合格线索最少。当成功定义没有定死时，团队会自然漂向最容易涨的那个数字。

**[pitfall-note-only] 只搜笔记不挖评论。** 真正表达具体需求的人大多在评论区而不是正文里，只采集笔记会漏掉意向最明确的一批人，且漏得毫无迹象。

**[pitfall-parsing-drift] 把解析口径变化当成人群变化。** 上游字段结构一变，整批人看起来都变了。归一化口径要有版本，跨版本的字段级差异要抑制。
